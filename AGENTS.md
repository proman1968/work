# Инструкции агенту: проект WORK

Язык общения, комментариев и документации — русский.

## С чего начинать каждую сессию

1. Прочитать **`docs/architecture-v2.md`** — утверждённая архитектура учётной системы и организационной модели WORK (по образцу ODANT).
2. Прочитать **`docs/work-v2-plan.md`** — поэтапный план работ (Этапы 0–5), протокол экономии токенов/моделей и журнал выполнения (раздел 3). Следующий шаг — **первый неотмеченный этап в журнале плана**.
3. Прочитать **`sources/data/progress.md`** — последние изменения и текущий статус.
4. Выдать пользователю короткий блок **«Рекомендация на шаг»**: модель, действие с сессией (продолжить / сжать `/compact` / новая сессия) и причина (экономия токенов и кэша).

## Протокол экономии денег и токенов

- **Основная рабочая модель — `Gemini 4 Argon` (`opencode/gemini-4-argon`, `high`):** у неё бесплатная запись в кэш (`Cache Write = $0`) и чтение из кэша по `$0.10 / 1M` (в 20–50 раз дешевле смены контекста на Opus/Sonnet).
- **Не менять модель внутри длинной сессии** — смена модели сбрасывает кэш промпта.
- **Разведку по коду (`explore`)** при большом объёме файлов делегировать субагенту на дешёвой модели (`opencode/claude-haiku-5-5` или бесплатной), чтобы не раздувать контекст основной сессии.
- **Сжимать сессию (`/compact`) или начинать новую** на границах крупных этапов (при контексте >120k токенов).

## Ключевые архитектурные правила (не нарушать!)

1. **Единственный UI — штатные вкладки проводника ODA (`work-form`).** Никаких отдельных приложений на Lit / Web Awesome. Во всех учётных формах сверху — полоса периодов `oda-packets`.
2. **Никаких искусственных `CID` (`cat.items`, `acc.41`).** Адрес любого класса — его путь в дереве WORK.
3. **Организационная модель и ограничения вложенности типов:**
   - `$class` — абстрактная развилка и **нигде не может создаваться** как экземпляр узла. Внутри любого типа разрешены `$file` и `$folder`, а допустимые дочерние типы жёстко ограничены родительским типом (`allowed_child_types` и `<мета>/$folder/$class/*`).
   - Внутри `$server` могут находиться только домены (`$domain`): `/ORGANIZATIONS` (`$domain`, внутри — `$base`), `/MODULES` (`$domain`, внутри — `$module`), `/DATA` (`$domain`, внутри — `$catalog`, `$struct`, `$operation`, `$register`).
   - У каждой `$base` — **своя изолированная БД** внутри её папки (`<Организация>/$base/#system/work.db`). Внутри `$base` допустимы `$structure`, `$base`, `$domain`, `$module`; внутри `$structure` — только `$structure`.
   - Трёхосевое наследование метаданных: `Types (миксины)` → `Ancestor (одноимённый класс в /MODULES)` → `Parent (родитель в дереве)` → `Сам класс`.
   - Подразделение (`$structure`) — точка коллаборации (`ADMIN`, `BOSS`, файлы, чат, задачи, `logs`). Рабочие места внутри подразделения — точки доступа сотрудников к учётным классам (`LINKS`: `read` / `write`).
4. **Классы данных и структуры:**
   - `$catalog` — реальные справочники (группы агрегируют объекты потомков, листья хранят объекты; отдельный `$registry` не использовать).
   - `$virtual` — виртуальные справочники от счёта (`mode: 'turnover'` по обороту или `mode: 'balance'` по ненулевому остатку на дату) + собственные поля `OVERLAY`.
   - `$struct` — составные структуры полей («Паспорт», «Адрес», «Строка накладной»). Табличная часть — это признак `table: true` у поля, а не отдельный тип `Table`.
5. **Явная двойная запись и двухэтапные аналитики:**
   - Проведение `$operation` создаёт отдельные записи в классе счёта Дебета (`$account`) и в классе счёта Кредита (`$account`), связанные общим `entry` и `op_id`, плюс пишет факт в `data.logs`.
   - Исправление проведённой операции — только через **сторно** (никакого тихого удаления истории).
   - Поля справочника-аналитики выступают как субаналитики (двухэтапный отбор: фильтр объектов справочника по полям → фильтр/группировка записей счёта по найденным `id`).

## Как проверять

- Запускать целевые тесты текущего этапа (`node --test tests/data-*.test.js`, `node --test tests/accounting-forms.test.js`, `node tests/ui/run.mjs accounting-forms`), не гоняя без нужды весь `npm test`.
- Dev-сервер: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev-server.ps1` (порт 8011, `WORK_DEV`).
- Консоль PowerShell искажает кириллицу — файлы читать инструментом `read`/`grep`, писать инструментом `edit`/`write` (или UTF-8 без BOM).
