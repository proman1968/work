1. Прочитать **`docs/work-v2-plan.md`** — план WORK v2 (10 дней), решения (Р1–Р15), журнал выполнения (раздел 6) и протокол работы с моделями (4b). Следующий шаг — **первый неотмеченный день в журнале**, а не пункт «В работе» из `progress.md`.

4. Работа вне плана — только по прямому указанию пользователя, с записью в журнал плана.

## Правила

- Интерфейс данных — **только Lit + Web Awesome**, без сборки, библиотеки локально (`vendor/lit`, `vendor/webawesome`, см. `vendor/README.md`). Lit без декораторов (`static properties`). Новый компонент Web Awesome — сначала в `components.js` страницы. Всё состояние — в `store.js`, компоненты наследуют `WorkElement`. Размер кнопок — `size="s"` (не `small`).
- **Формы ODA заморожены** (`form/objects`, журнал, ОСВ, карточка, состав, выбор места): не развивать и не чинить без блокировки; удаляются после паритета нового интерфейса. Проводник ODA остаётся «Конфигуратором».
- Чистую логику — в модулях без DOM с тестами в Node (стиль `tests/app-shell.test.js`, `tests/app-objects.test.js`); компоненты — в браузере (`tests/ui/*.html`, запуск `node tests/ui/run.mjs <имя>`).
- Ответы `db_*` меняются только добавлением полей: ODA-формы и агент от них зависят. Ошибки сервера приходят текстом (HTTP 400), поля из них разбирает `parseFieldErrors`.
- Известные падения полного `npm test` **не чинить** (12 шт., не связаны с WORK v2): `auth-register` (9), `agent-prompt`, `dev-tools` (нет `tsc`), `inherit-ops` («distributive»).
- `eslint` и `tsc` в среде не работают (нет зависимостей) — новый код ими не проверялся.

## Как проверять руками

- Dev-сервер: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dev-server.ps1` (порт 8011, `WORK_DEV`, DEV-пользователь — администратор). Скрипт может «висеть» в консоли — сервер при этом работает; проверка `http://localhost:8011/favicon.ico`. После добавления **новых файлов или папок** в дерево сервер перезапустить; правки существующих файлов подхватываются с задержкой в несколько секунд. После работы остановить: pid в `%TEMP%\work-dev-server.pid`.
- Страница: `http://localhost:8011/BASE/~/handlers//app/index.html`. Контекст в адресе: `#view=class&unit=unit.sales&place=head/manager&path=/DATA/OPERATIONS/Реализация` (кириллица кодируется).
- Скриншоты и скрипты в headless Edge: `node scripts/ui-shot.mjs <url> <out.png> [w] [h] [waitMs] [js]` — `js` выполняется на странице (есть `await`), переменные `CLICK`, `CLICK_WAIT`. Скриншот читать инструментом `read` по пути с **прямыми слэшами** (`C:/Users/Acer/AppData/Local/Temp/opencode/x.png`), иногда со второй попытки. `screenshot` через `tools.browser` не работает.
- Данные живой базы — `.data/work.db` (в `.gitignore`, на другом компьютере её нет): демо-данные создаёт `scripts/demo-seed.mjs`. Пробные объекты из ручных проверок в ней не важны.
- Консоль PowerShell искажает кириллицу в выводе — файлы читать инструментом `read`/`grep`; записывать UTF-8 **без BOM** (`[IO.File]::WriteAllText(..., (New-Object Text.UTF8Encoding($false)))`, а не `Set-Content`).
