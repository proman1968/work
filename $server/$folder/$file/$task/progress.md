# Прогресс: $task

## Последние изменения
- [14:35] Агенты исполняются движком класса (`~/ai prompt.$method`) через `_runAgent`: блок пушится в ленту, движку передаются `live` + `context({handoff})` + model/effort/tz. Причина: схлопывание двух реализаций в одну.
- [14:35] `_live(session)` — контракт ленты (send с path таска, save, stopped, mode, wait); `_resolveWait` доставляет ответ APPROVE ожидающему движку. Причина: стоп на стороне агента, задача только доставляет факт.
- [14:35] `context({handoff})` — передача агенту: диалог-улики без system/topicsMap/leafSystem, «кто/где» первым user-кадром. Причина: system пересобирает исполнитель.
- [14:35] `_promptTurn`: незавершённый агент доигрывает движок (восстановление после обрыва); внутри бокса-агента таск своим меню не ходит; `_push_block` не зовёт init агентов. Причина: один владелец жизненного цикла агента.
- [14:35] pipe-loader: агенты — декларации из меты класса (`ai/agents` через `$class.meta_folder`), тёзки ходов оркестратора пропускаются; каталог `$task/agents/*` удалён. Причина: канон агентов — `$class/ai/agents`, дубли рвут наследование.

## Ключевые решения
- Решение: стоп лист-агентов (question/form/planning/report) — прежний путь APPROVE/prompt таска; `live.wait` — только для стопов инструментов внутри бокса (activation). Причина: approve-хуки живут у владельца ленты (pipe/todo), поведение UI не меняется.
- Решение: `agent.model` строго побеждает `body.model` (движок). Причина: лёгкие модели агентов (gemma) не должны затираться моделью таска.
