# Форма задачи (.task) — микрочат агента

## 1. Что это

Представление `form/file` для `.task`: одна шапка (заголовок, статус, кольцо контекста), лента агента, план, композер; справа — доки (вкладки «Контекст», «Монитор», «Результаты», «Файлы»). ODA-компоненты на стилевой модели ODA (роли и токены `styles.js`: `--subtle-*`, `--accent-soft`, `--radius-*`, миксины `card`/`muted`/`chip`) — без сырых цветов.

## 2. Зачем это нужно

Человек видит, что делает агент (текст, рассуждение, действия с результатом и diff), отвечает на вопросы и подтверждает действия прямо в ленте, останавливает, откатывает и продолжает работу; результаты (файлы, отчёты, сводки) собираются в доках; статистика контекста — всегда под рукой.

## 3. Как это работает

- **Шапка одна.** Развёрнутая в чате (`chat-item`) — своя шапка с кнопкой закрытия; chat-item по событию `own-header` прячет свою полосу, `close-view` — сворачивает. В странице `form` (`work-form`) — шапка встраивается в её верхнюю панель (на место `slot[name=top-panel]`), своей нет.
- **Кольцо контекста** (% окна модели) — показ/скрытие доков; точка — появились новые доки, пока панель закрыта.
- **Доки.** Вкладка живёт в шелле (`dockTab`: `context | monitor | results | files`), открытый на «Файлах» файл — `dockFile`, результат — `resultKey`; на «Контекст» вкладка возвращается только если её больше нет.
  - **Файлы** (`ui/docs.js` `taskFiles`): *все* файлы задачи одним списком — вложения человека, созданное агентом (write/edit/append, таблицы, картинки, `export_pdf`, `render_doc`, выгрузка из песочницы, `call → save_files`, файлы субагентов) и опубликованные результаты; один файл — одна плитка с последней версией. Плитки — те же карточки `chat-item compact`, что и в ленте чата; клик открывает файл в доке («← Файлы» — к списку). Тот же список показывает карточка задачи в ленте чата (превью `.task`).
  - **Монитор** (`computerUse`): есть, если задача хоть раз пользовалась компьютером (`computer_*`, `browser_*`, `sandbox_*`), даже когда он уже удалён. Жив — живой экран; иначе подпись «выключен / удалён», последние скриншоты и команды из ленты. Имя компьютера — из аргументов вызовов.
  - **Результаты** — опубликованные результаты и отчёты субагентов; новый отчёт при открытой панели выбирается сам. Текстовый док — копировать, скачать, сохранить файлом `.md` в класс задачи.
- **Контекст** (`computeStats`): модель, провайдер, лимит, использование, токены (вход/выход/всего), рассуждение, сообщения, вызовы, даты, разбивка контекста последнего хода (`body.context` от ядра: system, схемы инструментов; диалог — оценка), исходные элементы ленты с JSON и экспорт сессии.
- **Лента**: подряд идущие действия — группа «N действий» (раскрыта, пока идёт работа или нужен человек; свёрнута по завершении). Стрим — `task.delta` → `streams[id]`; строка берёт более длинное из сохранённого и стрима.
- **Композер**: автовысота, Enter/Shift+Enter, Esc — стоп; вложения — «+», вставка, перетаскивание; диктовка (Web Speech API, где есть); меню режима, выбор модели, уровень рассуждения (если модель умеет), отправка/стоп.
- Данные — файл задачи: `changed` → перечитать (одна загрузка в полёте). Своя реплика видна сразу; лента держит низ, пока пользователь не отмотал (кнопка «вниз»; пока агент ждёт человека — «Агент ждёт вас»). Подписки на события задачи снимаются при смене задачи и уходе из DOM; Esc останавливает агента, если композер не обработал его сам.
- **Голосовой диалог** — кнопка со спектром (вертикальные полосы, нарисованы `work-voice-bars` в `prompt-bar.js`) в панели ввода вместо диктовки; в главном чате микрофон остаётся диктовкой. Выключена — полосы неподвижны, включена — движутся в такт голосу (ваш, пока слушаем; агента, пока говорит). Браузер просит микрофон при включении. Разговор поверх той же `.task`: речь → текст → обычная реплика (с пометкой `voice`) → ответ. Над композером — только лицо агента [`work-dot`](/$server/$folder/lib/dot/readme.md), без кнопок и подписей: на ваш голос меняет форму и цвет «вашим» цветом, на речь агента — цветом агента, ждёт вас / ошибка / готово — своим лицом; тап по лицу во время речи — замолчать. Маленьким лицо — в шапке задачи и в превью-карточке ленты.
  - *Слушает:* свои модели (`voice_config` → `sttModel`): микрофон, детектор речи по громкости (`Vad`), фраза уходит WAV 16 кГц в `voice_transcribe`; нет модели или её нет на шлюзе — `SpeechRecognition` браузера.
  - *Говорит:* `voice_speak` (`ttsModel`, Qwen3-TTS VoiceDesign) кусками (первый короткий — быстрый старт, дальше до 260 знаков) с упреждающей загрузкой следующего; сбой запроса повторяется, стойкий сбой — `speechSynthesis` с видимой причиной в тосте; браузерная речь держит ссылку на реплику (иначе Chrome обрывает её на первом слове). Громкость речи агента — из `AnalyserNode` (`AudioContext` создаётся в клике), громкость вашего голоса — `LevelMeter`; распознавание браузера перезапускается только по `onend`, а слова агента и 0,6 с после них (эхо) игнорируются. Отладка: `localStorage.workVoiceDebug = 1`. Говорящего можно перебить голосом (`bargeIn`), «стоп», тапом по лицу.
  - *Что озвучивается* (`ui/voice-policy.js`): начало ответа на реплику, сказанную голосом (агент знает об этом из `VOICE_NOTE`): связная проза до 3 предложений / 420 знаков (не только первый абзац — у модели он часто короткая вводная), список, таблица и код обрывают чтение; + «Подробности на экране», если есть что смотреть; вопросы агента с вариантами; просьбы о разрешении; ошибки. Ответ на набранный текст — молча. Код, таблицы, пути, рассуждения и карточки действий не читаются.
  - *Подтверждения — только на экране:* пока агент ждёт разрешения или подключения, голосовые фразы не отправляются (иначе они стали бы отказом с комментарием); на вопросы агента (`ask_user`) отвечать голосом можно. Команды: «стоп» — замолчать, «останови работу» — остановить агента.

## 4. Из чего это состоит

| Файл | Компоненты |
|---|---|
| [`file.js`](file.js) | шелл: размещение шапки, лента, план, композер, доки; состояние доков, стрима, групп |
| [`ui/feed.js`](ui/feed.js) | `microchat-feed` (`segmentsOf`), `-user`, `-assistant`, `-steps`, `-think`, `-tool` (статус, аргументы, результат, diff, подтверждение, вопрос, лента субагента), `-field`, `-summary`, `-error`, `-todos` |
| [`ui/panel.js`](ui/panel.js) | `microchat-panel` (композер), `microchat-menu` (выпадающий выбор) |
| [`ui/dock.js`](ui/dock.js) | `microchat-header`, `microchat-dock`, `microchat-context`, `microchat-monitor`, `microchat-results`, `microchat-files`, `microchat-doc` |
| [`ui/docs.js`](ui/docs.js) | `collectDocs`, `taskFiles`, `computerUse`, `computeStats` (чистые функции) |
| [`ui/util.js`](ui/util.js) | названия/иконки инструментов, форматтеры, `findShell` |
| [`ui/voice.js`](ui/voice.js) | `Vad`, `encodeWav`, `MicCapture`, `Speaker`, `VoiceController` (логика голосового режима, без ODA) |
| [`ui/voice-policy.js`](ui/voice-policy.js) | чистые правила «что и когда озвучивать»: `speakable`, `leadOf`, `replyPlan`, `attentionText`, `voiceCommand` |
| [`ui/voice-ui.js`](ui/voice-ui.js) | `microchat-voice` — только лицо над композером: состояние по контроллеру и статусу задачи; тап во время речи — замолчать |

Сервер голоса — методы `$task`: `dot_look` (внешний вид персонажа), `voice_config`, `voice_speak`, `voice_transcribe` (`sources/modules/agent/voice.js`); модели — `ai/config.js` `ttsModel` / `sttModel` (`/MODELS/odant/Qwen3-TTS`, `/MODELS/odant/Qwen3-ASR`).

## 5. В каком это состоянии

Пустой задачи не бывает: задача всегда создаётся запросом или файлами. Карточка задачи в ленте чата получает быстрые действия (остановить, ответить вариантом на вопрос, продолжить; разрешения — только в раскрытой задаче). Тесты: `tests/ui/task-dock.html` (настоящий шелл: вкладки, файлы, монитор), `tests/ui/voice-ui.html`, `tests/task-docs.test.js`, `tests/voice-policy.test.js`.

Работает на ленте v2; проверено скриншотами (`scripts/ui-shot.mjs`, в т.ч. клики `CLICK=x,y`) в странице form и развёрнутым в чате, на живых прогонах (вопрос → ответ кнопкой → продолжение).

## 6. Дальнейшие планы

- Редактирование реплики на месте (сейчас — откат с возвратом текста в поле ввода).
- Голос: Silero VAD вместо порога по громкости, потоковая озвучка (WebSocket `/v1/audio/speech/stream`, когда шлюз начнёт отдавать звук по мере генерации), распознавание Qwen3-ASR после установки.
