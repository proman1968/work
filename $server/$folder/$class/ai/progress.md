# Прогресс: $class/ai

## Последние изменения
- Движок меню-агентов (выбор id хода текстом + 17 агентов-боксов, `ai/task.js`, `prompt/$method` на 1100 строк) заменён ядром на нативном tool calling — `sources/modules/agent`. Причина: модель сама выбирает инструменты и аргументы (JSON-схемы), параллельные чтения, разрешения, субагенты, навыки-инструкции; прежний движок добывал операнды отдельными вызовами LLM и держал знание каталога/триггерные фразы в коде.
- Пакет `ai/` — только данные: `system.md`, `config.js`, субагенты `agents/*.md`, навыки `skills/*.md` (фронтматтер + markdown). Слои: пакет движка → метапапки классов от корня к месту.
- `prompt/$method` — разовый REST-запуск на ядре (`runOnce`), без ленты на диске.
- Навык `register-accounts` переписан рецептом в markdown (был `pipe` шагов прежнего движка).

## В работе
- Матрица сценариев на живой модели (`scripts/agent-run.mjs`): дерево, запись, журнал, веб, вопросы/подтверждения, навыки, MCP.

## Ключевые решения
- Решение: ядро — обычные Node-модули в `sources/`, поведение — данные в дереве. Причина: цикл, разрешения и сессия — инфраструктура (тестируемость, `node:*`); место настраивает агента без кода (`system.md`, навыки, субагенты, config).
- Решение: знание каталога — не в коде ядра. Причина: агент узнаёт место из контракта (собранный readme) и инструментов; пути `/BASE`, `/REGISTER` и т.п. живут только в навыках и readme мест.
- Решение: права — ядра WORK, не агента. Причина: каждый вызов инструмента идёт с `session` пользователя; политика разрешений агента — дополнительный слой поверх (подтверждение изменений системы).
