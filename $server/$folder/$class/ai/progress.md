## Ключевые решения
- Решение: remote и stdio — один класс, разница в полях (`url/headers` vs `command/args/env`). Причина: модели один список реестра и один вызов; транспорт — деталь провайдера.
- Решение: запрос к англоязычному индексу — только по-английски (тихая переформулировка, паттерн web.js). Причина: русская фраза даёт стабильный мусор.
- Решение: `\b` не работает после кириллицы — границы слов только через `(\s|$)`. Причина: поймано тестом (`ещё` не матчилось).
- Решение: выбор человека — композицией (вложенный `form`), не новым UI. Причина: форма/approve/wait уже проверены; дублировать механику выбора запрещено.
- Решение: повтор без новой информации — заблокирован, даже успешный (сверка побайтово с сиблингом). Причина: успех со старым контентом — тоже холостой ход; перечитывание изменившегося разрешено.
- Решение: blacklist = «не раскрывать», а не «не показывать»: тяжёлое видно первым уровнем. Причина: полная невидимость ломает легитимные вопросы управления системой.
- Решение: вид цели не тот ≠ ошибка: редирект несёт state без error. Причина: красный — только провалам; редирект не должен жечь errorStreak и пугать.
- Решение: инструкции — readme.md в точке применения (`SERVICES/readme.md`), указатели — по строке, решения — в progress. Причина: модель открывает readme места работы; дублирование текста в указателях запрещено.
- Решение: установка внешнего — только через `work` (его activation), своего гейта у `mcp` нет. Причина: один гейт записи на всех, не плодить approval-механики.
- Решение: имя бокса-агента неизменно, заголовки генерируются только листам. Причина: переименование по контенту уничтожает идентичность в ленте.
- Решение: tool-константа без ключа в `export default` — мёртвый код: проверять `hasTools` декларации. Причина: `registerAgent` считает `box` по факту wiring, молчаливый лист вместо агента.
- Решение: вердикт модели — в поле блока, не только в прозу. Причина: следующий шаг не может потребить текст; парсер честных сигналов (`✅/ставить`), не смысла.
- Решение: act-инструменты — только в build за approval; гейт «activation после чтения» — лишь агентам с read. Причина: inform-задача не должна видеть install в меню; движковый гейт без read прятал бы activation навсегда.
- Решение: «хода нет» — это skip, не error; доступность возвращается вердиктом (re-arm). Причина: красный из ничего + вечный повтор того же хода.
- Решение: нового tool нет — расширяем `map`/`ls` тремя списками. Причина: отдельный tool жрёт слот меню и ход, fallback мешает evidence; три секции видны меню без новых типов.
- Решение: ключ ветки агента и `body.mode` — одно имя `build`. Причина: движок читает `agent[mode]`.
- Решение: ошибка create не жжёт ход; activation без ok read не в меню. Причина: write фразой в отсутствующий путь ломал второй work.
- Решение: после принятой activation меню build = create. Причина: pick search/write вместо create в несуществующий путь.
- Решение: пакет агентов не знает прикладной каталог. Причина: `if (type === '$ai')` в work — не принцип create.
- Решение: инварианты формулируются универсально, без триггер-фраз задачи. Причина: правка под конкретный прогон ломает автономное развитие.
- Решение: провенанс ставит код агента, не текст инструкции. Причина: контент read/meta заполняет `exec`, модель заголовок дописать не может.
