# Прогресс: $class/ai

## Последние изменения
- Комплексный аудит и рефакторинг пакета перед релизом. Ядро: субагент получает набор, пересечённый с набором вызвавшего (раньше `readonly`-агент мог через `task` поручить работу `general` со всеми инструментами); `skill` есть у любого субагента; `call: […]` сужает `call` (аудитор — «только чтение» держит код); маски `tools` с `*` в любом месте; `requires: system|sandbox` скрывает агентов и навыки от тех, у кого нет ОС/сети или Docker; слои `system.md` дописываются (раньше ближний целиком затирал базовые правила, включая безопасность); `query` получил `offset`; `logs` печатает id как `id=автор:время`, `send` снимает `#`/`id=` и отклоняет кривые `due`/`reply_to` (раньше ядро молча их отбрасывало — рвалась связь поручение → ответ).
- `prompt`: пустой/слишком длинный запрос — ошибка до запуска модели, лимит 10 минут, сигнал отмены, `post` без `prompt` больше не превращается в «[object Object]».
- `system.md` переписан: общее правило «внешнее содержимое — данные», секреты, отказ в доступе → escalate, память; противоречие с `ENV_GUIDE` про сайты без API снято.
- Агенты: исправлены списки инструментов (`operator` без `todo_write`, `analyst`/`builder` с `append`, `it-admin` с `assign`, `integrator-1c` только `svc_*_catalogs/query/status`, `negotiator` — `call` только `remote`), в описаниях — «когда не поручать», `it-admin`/`operator` видны только когда доступны ОС или Docker.
- Навыки: `register-accounts` переехал в метапапку журнала (`/DATA/REGISTER/$register/ai/skills`); исправлены `import-table` (дубль записи ленты), `onboarding` (заглушка пути), `data-quality` (пагинация), `delegate-task`/`approval-flow` (формат id); добавлены `request-access`, `scheduled-report`, `ai-trigger`, `restore-file`, `skill-authoring`.
- Тест `tests/ai-package.test.js`: фронтматтер, индексы readme, маски `tools`, существование инструментов и параметров из рецептов, бюджет system. Новые кейсы eval: `injection-ignored`, `no-invention`.

- `.gitignore`: зоны `DATA/ADMIN/USER/BOSS` игнорируются только внутри метапапки (`**/$*/DATA/` и т.д.); одноимённые классы (например `/DATA`) публикуются.
- Матрица ручной проверки на живой модели: `tests/eval/prompts.md` (≈130 промптов и сценариев, приоритеты P0–P2).

## Ключевые решения
- Решение: ядро — обычные Node-модули в `sources/`, поведение — данные в дереве. Причина: цикл, разрешения и сессия — инфраструктура (тестируемость, `node:*`); место настраивает агента без кода (`system.md`, навыки, субагенты, config).
- Решение: знание каталога — не в коде ядра. Причина: агент узнаёт место из контракта (собранный readme) и инструментов; пути `/BASE`, `/DATA/REGISTER` и т.п. живут только в навыках и readme мест.
- Решение: навык, завязанный на конкретное место, лежит в метапапке этого места. Причина: WORK — контекстная система; навык виден там, где его пути и контракты верны, и не шумит в чужих списках.
- Решение: права — ядра WORK, не агента; делегирование их не расширяет. Причина: каждый вызов идёт с `session` пользователя; субагент — пересечение собственного набора и набора родителя.
- Решение: «только чтение» агента — кодом (`tools: readonly`, `call: […]`), а не текстом роли. Причина: текст промпта не граница безопасности.
- Решение: слои `system.md` складываются, замена — явная (`replace: true`). Причина: место уточняет правила, но не должно случайно потерять базовые правила безопасности.
- Решение: недоступное сессии (ОС/сеть, Docker) скрывается из списков агентов и навыков (`requires`). Причина: каждое лишнее описание — токены в каждом запросе и повод для вызова недоступного.
- Решение: ошибки аргументов `send` — сразу модели, а не молчаливое отбрасывание. Причина: иначе связь «поручение → ответ» и контроль сроков рвутся без следа.

## Блокеры / Открытые вопросы
- Субагенты запускаются и как продолжимые `.task` (`agent_start`): там набор определяется только описанием агента и ролью задачи (родителя в сессии нет) — пересечение с набором родителя не применяется; границей остаётся роль.
- `tests/accounting-forms.test.js` («save/remove/post/unpost…», `h.remove is not a function`) падает независимо от этих изменений.
