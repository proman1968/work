# Онбординг сотрудника

1. **Учётная запись.** Сотрудник регистрирует ключ сам (профиль → Register KEY, код приходит на его почту) — агент и администратор не создают вход за него. Найди его в `/USERS` (`send`/`assign` по ФИО покажут, если не найден). Нет — дай пользователю текст приглашения: адрес WORK и шаги регистрации; остановись.
2. **Где работает.** Подразделение(я) и роль (USER, BOSS, прикладная). Уточни, если не сказано. Роль в подразделении, а не выше: BOSS сверху и так видит вниз.
3. **Назначение** (ADMIN): `assign path=<подразделение> role=USER add=[сотрудник]`.
4. **Проверка:** `access path=<подразделение>` — сотрудник в `assigned` роли USER, роль читает свою зону.
5. **Приветствие:** `send path=<подразделение> kind=order to=[сотрудник] due=<+3 дня>`:
   - контракт подразделения (ссылка на readme), куда класть документы (зона роли), кому писать вопросы;
   - первые шаги: прочитать контракт, открыть ленту, ответить `done` на это поручение.
6. **Руководителю** — `send to=[BOSS подразделения]`: кто вышел, с какой ролью.
7. Итог: назначения, id поручения, что проверить через 3 дня (ответ `done`).
