# Импорт таблицы

1. **Таблица:** `read_table path=<файл>` — листы, колонки, первые строки, всего строк.
2. **Куда:** лист справочника или операции под `/DATA` (`call db_schema` класса — поля с наследованием, `leaf`, `family`). Нет подходящих полей — это задача builder, не импорта.
3. **Сопоставление** колонок → полей (`map`); у операций колонку даты сопоставь с `time`. Покажи пользователю таблицу сопоставления и что будет пропущено (неизвестные поля не пишутся).
4. **Пробный прогон:** `import_objects … dry_run:true` — ошибки обязательных полей, неизвестные поля, пример объектов. Исправь `map`/данные.
5. **Дубли:** если в классе уже есть объекты — `call db_query` с `search` или `where` по ключу (код, ИНН); повторы не импортируй, перечисли их пользователю.
6. **Импорт** (с подтверждением): `import_objects …` частями до 1000 строк (`read_table offset/limit` → `rows`). Ошибки строк (тип, ссылка, лишнее поле) — в `failed`.
7. **Проверка:** `call db_query` — число новых объектов совпадает; 2–3 объекта `call db_read` выборочно. Операции импортируются черновиками — проведение (`db_register`) отдельно, по просьбе.
8. Итог: сколько создано, пропущено (почему), в каком классе. Запись в ленту класса об импорте `import_objects` делает сам — вручную не дублируй.
