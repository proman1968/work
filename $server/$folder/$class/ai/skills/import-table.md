# Импорт таблицы

1. **Таблица:** `read_table path=<файл>` — листы, колонки, первые строки, всего строк.
2. **Куда:** лист справочника (`$catalog`) или операции (`$operation`) в модуле организации (`/ORGANIZATIONS/<Организация>/MODULES/Register/...`): вызови `describe_class` (или `call` метода `db_schema` класса — поля с наследованием, `leaf`, `family`). Нет подходящих полей — это задача builder, не импорта.
3. **Сопоставление** колонок → полей (`map`); у операций колонку даты сопоставь с `time`. Покажи пользователю таблицу сопоставления и что будет пропущено (неизвестные поля не пишутся).
4. **Пробный прогон:** `import_objects` с `dry_run: true` — ошибки обязательных полей, неизвестные поля, пример объектов. Исправь `map`/данные.
5. **Дубли:** если в классе уже есть объекты — `find_objects` (или `call` `db_query`) с `search` или `where` по ключу (код, ИНН); повторы не импортируй, перечисли их пользователю.
6. **Импорт** (с подтверждением): `import_objects` частями до 1000 строк (`read_table` с `offset`/`limit` → `rows`). Ошибки строк (тип, ссылка, лишнее поле) — в `failed`.
7. **Проверка:** `find_objects` — число новых объектов совпадает; 2–3 объекта проверь выборочно. Операции импортируются черновиками — проведение (`register_operation`) отдельно, по просьбе.
8. Итог: сколько создано, пропущено (почему), в каком классе. Запись в ленту класса об импорте `import_objects` делает сам — вручную не дублируй.
