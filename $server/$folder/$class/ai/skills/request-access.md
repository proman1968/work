# Запрос доступа

1. **Не обходи.** Другой путь, другая роль, копия файла — запрещено; отказ — не ошибка для повтора.
2. **Выясни причину:** `access path=<элемент>` — область элемента, какие роли его читают и меняют, кто на них назначен, твои роли здесь (`yourRoles`). Роль «шляпы» задачи выбрана пользователем: из ADMIN-действий в чужой роли доступа не будет — так и скажи.
3. **Что именно нужно:** чтение (`read`), запись (`write`), роль (`role:<РОЛЬ>`) или решение (`decision`). Не проси больше нужного.
4. **Покажи пользователю** (одной фразой): к чему, зачем, у кого просим — и дождись согласия, если он ещё не просил этого.
5. **Запрос:** `escalate path=<элемент> need=<read|write|role:РОЛЬ|decision> reason=<зачем, по-человечески, без секретов>`. Адресат находится сам: руководитель точки (BOSS) → вышестоящий → администратор. Запомни id из ответа.
6. **Ответ** придёт `done`/`reject` в ленту кабинета; следи по `logs` кабинета (`reply_to` = id). Нет ответа — напомни пользователю, `send kind=remind` только по его просьбе.
7. Итог: кто получил запрос, id, что делать дальше; работу, не требующую этого доступа, продолжи.
