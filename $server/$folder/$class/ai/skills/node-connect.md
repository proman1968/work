# Подключение узла сети

1. **Адрес партнёра** (https://…) и цель: кто кому что даёт (мы покупатель — у них роль CUSTOMER; они у нас — роль в нашей точке продаж).
2. **Карточка** (ADMIN): `call path=/NODES method=node_add args={origin}` — ответ содержит id узла, название и **отпечаток ключа**. Попроси пользователя сверить отпечаток с администратором партнёра по независимому каналу (телефон, письмо). Без сверки не продолжай.
3. **Добавление:** `call path=/NODES method=node_add args={origin, fingerprint, label, announce}` — узел закреплён в `/NODES/<имя>`.
4. **Наши представители у партнёра:** в `/NODES/<имя>` видны роли партнёра (`ROLES`); назначь наших пользователей — `assign path=/NODES/<имя> role=CUSTOMER add=[Иванов]`.
5. **Партнёр у нас** (если он тоже работает с нами): `assign path=<наша точка> role=<роль> add=[<id узла партнёра>]` — узлу выдаются только роли, допускающие узлы (не ADMIN/BOSS).
6. **Ответная сторона:** партнёр делает шаги 2–5 у себя (добавляет наш сервер, назначает его на свою точку). Наш отпечаток — в `/.well-known/work-node`.
7. **Проверка:** `call path=/NODES/<имя> method=node_refresh` — `remote.grants` показывает, какие точки и роли выданы нашему серверу; пробное чтение `remote as=<роль> path=<точка> method=info`.
8. Итог: узел, отпечаток (сверен кем), представители, выданные нам и партнёру роли.
