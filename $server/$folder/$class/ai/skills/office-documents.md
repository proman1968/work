# Офисные документы

## Маршруты по форматам

1. **Читать:** `read` извлекает текст из PDF, DOC, DOCX, XLSX (и показывает класс/контракт). Старые `.doc`/`.xls` — только входной формат, новые документы создавай как `.docx`/`.xlsx`.
2. **Таблицы:** `read_table path=<файл>` — листы и строки; `import_objects` — строки в объекты WORK (сначала `dry_run`, дубли не импортируй); `write_table` — отчёт `.xlsx`/`.csv` из данных.
3. **Документы по шаблону:** `render_doc template=<шаблон> path=<результат> data={…}` (docx/md/html/txt, метки `{{поле}}`). Результат — того же расширения, что шаблон. Полный рецепт (поиск шаблона, сбор данных, проверка) — навык `doc-from-template`.
4. **Настоящий PDF:** только из HTML через `export_pdf source=<файл.html> path=<файл.pdf>`. Прямого создания PDF из DOCX/MD/TXT нет — сначала собери HTML-версию.

## PDF: требования к HTML

- `@page { size: A4; margin: 12–15mm }`, системные шрифты (`Arial, Helvetica, sans-serif`), весь CSS — инлайн в `<style>`.
- Никаких внешних ресурсов (картинки — только встроенные, шрифты — только системные): при рендере сеть заблокирована.
- Кириллица — в UTF-8 с `<meta charset="utf-8">`.
- Проверка: `read` готового PDF (текст должен извлекаться, порядок разделов — как в HTML), размер — не байты.

## Правила документов для клиентов (КП, договоры, счета)

- Цены, реквизиты, сроки, подтверждённые возможности — только из источников (объект WORK, шаблон, слова пользователя). Нет данных — пиши «по запросу» / «уточнить», не выдумывай цифры.
- Итог пользователю: путь PDF, источник данных, что проверить человеку, отметь результат через `publish`.
