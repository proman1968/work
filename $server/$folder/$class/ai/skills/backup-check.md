# Резервные копии

1. **Где копии:** спроси или найди — `os_ls`/`os_find name=*.zip|*.7z|*.tar*|*backup*` в типичных местах (другой диск, сетевая папка `\\сервер\…`, `/var/backups`). Служба/задача копирования — `os_services filter=backup`, на Windows ещё `shell` `Get-ScheduledTask | ? TaskName -match 'backup'` (подтверждение).
2. **Свежесть:** дата последней копии (`os_stat`), размер против размера дерева WORK (`os_info`, диск). Старше суток или заметно меньше обычного — риск.
3. **Состав:** в копии должно быть дерево WORK (кроме `node_modules`, `.index` можно восстановить переиндексацией), обязательно `#system` (ключ сервера `node-key.json`, VAPID, настройки) и `USERS` (ключи пользователей). Содержимое архива — `shell` со списком файлов (без распаковки секретов в чат).
4. **Место:** свободно на диске WORK и диске копий (`os_info`); при < 15 % — крупные файлы `os_find` (логи, временные).
5. **Проверка восстановления** — раз в месяц: предложи администратору развернуть копию на отдельной машине; сам не восстанавливай поверх рабочего дерева.
6. **Отчёт:** последняя копия (где, когда, размер), что не входит, место на дисках, рекомендации. По просьбе — `schedule` еженедельной проверки.
