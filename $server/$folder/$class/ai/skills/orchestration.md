# Оркестрация: несколько агентов + сбор результата

## Когда оркестрация нужна

Поручение распадается на НЕЗАВИСИМЫЕ части (каждая завершается сама по себе) и
части ТРОГАЮТ ОДНИ ФАЙЛЫ. Чтения параллелятся всегда; запись — только через ветки.

## Шаги

1. **Декомпозиция.** Разбей работу на части, для каждой: цель, пути, что прочитать,
   что написать. Части не должны зависеть друг от друга; зависимые части делай сам после сбора.
2. **Чтения — параллельно.** Независимые субагенты (`task` с `tools: readonly`-масками)
   по одной части: «прочитай и верни факты с путями». Их вызовы идут параллельно сами.
3. **Записи — изолированные ветки (`branch`).**
   - `branch create path=<зона>` → путь ветки (копия рядом с оригиналом, права наследуются; временная — после сбора убери);
   - субагент(ы) работают В ВЕТКЕ (`read`/`write`/`edit` по путям ветки — параллельно, не мешая друг другу);
   - `branch status path=<ветка>` → что изменилось, есть ли конфликты (оригинал менялся);
   - `branch merge path=<ветка>` → перенести изменения в оригинал (каждый файл — с историей и откатом; человек подтверждает); конфликтный файл перезапишет изменившийся оригинал — прежняя версия останется в истории; проверь после;
   - `branch drop path=<ветка>` → убрать ветку.
   Одна ветка — один субагент или один смысл; несколько веток — несколько параллельных писателей.
4. **Сбор.** `branch merge` переносит содержимое файлов **напрямую, вне твоего контекста**:
   прочитанное и написанное субагентами не проходит через твоё окно — собирай большие результаты
   ветками, а не чтением в ленту. Сведи отчёты субагентов в один итог: что сделано (по файлам),
   конфликты и как решены, что проверить человеку. Отчитывайся по каждой части.
5. **Повтор шага.** Шаг не получился — просто запусти субагента снова НА ТУ ЖЕ ВЕТКУ
   (`task` с прежним путём ветки в prompt): уже сделанное в ветке сохраняется, субагент
   продолжает с места остановки. Отчёт субагента скажет, что осталось.
6. **Остановка ветки.** Затянувшийся субагент — `agent_stop` (его `.task`), после —
   `branch drop` для самой ветки. Записи субагента до остановки остаются в его ленте.

## Правила

- Субагент не получает больше прав, чем ты (пересечение наборов); подтверждения веток и merge — у человека.
- Merge большой ветки проверяй статусом до: конфликты лучше разрешить до переноса (прочитай обе версии).
- Не оставляй ветки после сбора: `branch drop` (или скажи человеку, что осталось).
- Свою модель и лимит ходов субагент берёт из фронтматтера (model, maxTurns) — доменные роли уже настроены (analyst, developer, it-admin, auditor и другие из списка).
