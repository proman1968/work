# ai/agents — субагенты

Субагент — отдельный агент со своим контекстом и набором инструментов; основной агент поручает ему подзадачу инструментом `task` (`agent`, `description`, `prompt`) и получает его итоговый отчёт. Независимые поручения выполняются параллельно. Лента субагента хранится внутри карточки вызова (`tools[].items`) и видна в UI. Долгую независимую работу основной агент запускает продолжимым `agent_start` (отдельная `.task`).

Файл `имя.md`:

```md
---
name: explore
description: Когда поручать и когда нет (по этому описанию выбирает основной агент)
tools: readonly            # readonly | * | [ls, read, web_*, svc_*_query]
call: [members, security_log]   # необязательно: разрешённые методы инструмента call
requires: system           # необязательно: system | sandbox — виден, только если это доступно
model: /MODELS/…           # необязательно: своя модель
maxTurns: 40               # необязательно
---
Роль и правила субагента (добавляются к общему system).
```

## Правила набора инструментов

- Маска в `tools`: `*` внутри имени — любая подстрока (`os_*`, `svc_*_query`).
- Субагент **не получает больше инструментов, чем есть у вызвавшего** (набор пересекается с набором родителя): делегирование права не расширяет. Роль и права — те же, что у задачи.
- Всегда недоступны: `ask_user`, `todo_write`, `save_skill`, `schedule`, подключение сервисов. Недостающее у человека субагент перечисляет в отчёте.
- Всегда доступен `skill` (чтение навыков): список навыков входит в его system.
- Инструменты ОС и сети (`os_*`, `net_*`, `shell`) — только при явном перечислении, у администратора и в роли ADMIN; `*`/`readonly` их не включают.
- `call: […]` сужает `call` до перечисленных методов (остальное отклоняется до подтверждения): так «только чтение» у аудитора держится кодом, а не только текстом роли.
- Вложенность — не глубже 2.
- `requires: system` — агента не видят те, у кого нет ОС/сети (не ADMIN); `requires: sandbox` — когда Docker недоступен.

Подтверждения изменений субагент получает у человека через ту же задачу, что и основной агент.

| Субагент | Назначение |
|---|---|
| [`explore`](explore.md) | исследование дерева только на чтение, отчёт с путями |
| [`web`](web.md) | исследование в интернете, факты со ссылками |
| [`general`](general.md) | самостоятельная подзадача со всеми инструментами |
| [`analyst`](analyst.md) | отчёты и сводки по объектам, лентам и документам; таблицы xlsx/csv |
| [`secretary`](secretary.md) | входящие, поручения с получателями и сроками, контроль исполнения |
| [`auditor`](auditor.md) | аудит доступа и журнала безопасности — только чтение и рекомендации |
| [`builder`](builder.md) | прикладная модель: типы, поля объектов, роли и зоны, контракты readme |
| [`it-admin`](it-admin.md) | сервер WORK и его локальная сеть: здоровье, службы, устройства (только ADMIN) |
| [`integrator-1c`](integrator-1c.md) | чтение 1С по OData, выгрузка и сверка с объектами WORK |
| [`negotiator`](negotiator.md) | действия представителя на серверах-партнёрах сети |
| [`reviewer`](reviewer.md) | ревью изменений class.js, методов и контрактов — только чтение |
| [`operator`](operator.md) | персональный компьютер пользователя: команды, экран, браузер (нужен Docker) |

Проверяет состав и согласованность `tests/ai-package.test.js`.
