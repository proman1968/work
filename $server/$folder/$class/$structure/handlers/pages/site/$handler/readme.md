# Site — сайт точки оргструктуры (handlers/pages/site)

Один page-хендлер `site` в трёх слоях наследования. Ближний слой переопределяет
`template` и жизненный цикл (`ready`/`attached`/`detached`) нижнего, остальное
(геттеры, методы) берёт склейкой `~`.

| Слой | Точка | Что показывает |
|---|---|---|
| `$structure/handlers/pages/site` | подразделение (`$structure`), должностная группа (`$group`) | Рабочая зона: описание, руководство и сотрудники, дочерние подразделения и группы, рабочие ссылки (`link_tree`) |
| `$structure/$base/handlers/pages/site` | организация (`$base`) | Сайт организации: навигация по подразделениям слева, справа — главная (корень) или сайт выбранного узла в iframe |
| `$structure/$server/handlers/pages/site` | WORK | Лендинг: презентация платформы, возможности, вход, сайты организаций |

Обычные `$class` (данные, справочники) сайта не получают: слоёв в их цепочке нет.

Открытие: `{точка}/~/handlers//site/index.html`

## Общее

- Вход/аватар/explorer — `lib/site-user` (`item-site-user`, только в top-окне).
- Узлы структуры и локация — `lib/site-loc` (`structureKind`, `isStructureNode`, `#ctx=…`).
- Рабочие ссылки — сырой `WORK.fetch(..., 'link_tree')` (без `__bind`: узлы — данные, а не элементы).

## Вложенность

Сайт организации ставит в своём окне `window.__workSiteShell = { open(short), loc(win, loc) }`.
Вложенный сайт (iframe, тот же origin) через него выбирает узел в навигации и сообщает свою
локацию; без оболочки — обычная навигация и `#ctx=…` в адресе.

## Правила

- Объявления `ODA({ is })` и классы верхнего уровня не повторяются между слоями: при склейке
  верхнеуровневый код всех слоёв конкатенируется.
- Узлы навигации — экземпляры класса (`SiteOrgNode`), не plain-объекты: Reactor копирует
  объектные поля plain-объектов (`$def`), ссылка на элемент WORK потерялась бы.
