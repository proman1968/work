# app — рабочее место подразделения (Lit + Web Awesome)

Страница `app` открывается на подразделении (`$structure`, `$base`): `{подразделение}/~/handlers//app/index.html`, например `/BASE/~/handlers//app/index.html`. Это интерфейс работы с данными по плану WORK v2 (дни 6–8) вместо форм ODA: без сборки, библиотеки локально — `vendor/lit`, `vendor/webawesome` (см. `vendor/README.md`).

## Как это устроено

- `app.js` — единственный элемент ODA: точка входа страницы WORK (вход, `$item`). Подгружает тему и оболочку, создаёт хранилище и кладёт `<work-app>` в `body`.
- Пользователь и меню приходят одним вызовом `db_workspace` на подразделении страницы (`sources/data/workspace.js`): подразделения и места пользователя, меню каждого места (ссылки места на классы по слоям: операции, справочники, журнал и счета), контексты работы и описание классов с поддеревьями. Права по-прежнему проверяет сервер на каждом вызове; меню — только описание.
- **Контекст** = подразделение + место. Живёт в адресе (`#view=class&unit=unit.sales&place=head&path=/DATA/…`), запоминается в localStorage (`work.ctx:<корень>`). Откуда берётся при открытии: адрес → сохранённый → первое своё место → подразделение. Смена контекста открывает главную: у другого места другое меню.
- **Навигатор** (шапка): кнопка с текущим «Подразделение / Место» и дерево «мои подразделения и места». Подразделение без прав — только каркас (путь до нижних); BOSS и ADMIN выбирают подразделение целиком (сводный вид) и видят все места на чтение.
- **Меню** места: свои ссылки — со своим доступом, ссылки вложенных мест — на чтение, общие ссылки подразделения — как есть; ссылка ниже другой ссылки не дублируется и лишь повышает доступ в своей ветке. «Глаз» у пункта — только чтение; в подсказке — видимость данных (`scope`).

## Модули

| Файл | Что |
|---|---|
| `router.js` | адрес ↔ маршрут (`view`, `unit`, `place`, `path`, `id`, `params`) |
| `menu.js` | чистые функции: контекст, меню, дерево навигатора, крошки, подписи прав |
| `api.js` | клиент `db_*` (`WorkApi`, `ApiError`) — не зависит от ODA |
| `store.js` | состояние: пространство, контекст, маршрут, синхронизация с адресом (`AppStore`, `app`) |
| `vendor.js`, `components.js`, `theme.css` | тема (токены Web Awesome + наши, светлая/тёмная), русские подписи, список компонентов |
| `icon.js` | `<work-icon name="набор:значок">` из спрайтов проекта, с запасным значком |
| `shell.js`, `org-nav.js`, `menu-view.js` | оболочка (`wa-page`), навигатор, меню |
| `view-home.js` | главная: слои, права места |
| `view-class.js` | экран класса: по схеме (`db_schema`) выбирает список, форму (в адресе `id`), состав виртуального справочника или паспорт |
| `obj-list.js`, `list-model.js` | список: поиск, статус, период, фильтры по полям, сортировка, страницы — параметрами `db_query`; состояние в адресе (`q`, `status`, `from`, `to`, `order`, `page`, `f.<поле>`) |
| `obj-form.js`, `lifecycle.js` | форма объекта: поля по схеме, действия по статусу («Зарегистрировать / Исправить / Отменить / Печать»), проводки, место записи |
| `field-input.js`, `link-input.js`, `table-input.js` | ввод по типу, ссылка (`db_choices`: состав на дату, «показать всех», «создать» в окне), табличная часть |
| `fields.js`, `entries.js`, `class-tree.js` | чистая логика: значения формы ↔ тело, проверка, подписи, проводки, выбор листа для создания |
| `view-members.js`, `view-passport.js` | состав виртуального справочника (чтение) и паспорт класса (счета, журналы, подразделения — отчёты в день 8) |

## Список и форма

- **Адрес:** список — `#view=class&path=<класс>&q=…&page=2`, форма — `…&id=<id объекта>`, новая — `…&id=new&cls=<путь листа>`. Возврат «К списку» сохраняет поиск и страницу.
- **Запись** идёт на лист класса объекта (по `cid` → путь в `ws.classes`), чтение — на класс списка. Сохранение черновика и справочника — замена тела целиком с версией; проведённая операция — `db_correct`; новая операция — `db_create` (место записи из контекста или выбор), затем `db_register`.
- **Ошибки сервера** по полям (`DataError`) разбираются из текста ответа (`ApiError.errors`, `parseFieldErrors`) и показываются у поля или ячейки (`lines[2].qty`).
- Пустые строки табличной части перед отправкой убираются — номера строк у сервера и на экране совпадают.

## Правила

- Только Lit без декораторов (`static properties`), без сборки; импорты библиотек — абсолютные (`/vendor/...`), своих модулей — относительные.
- Компонент Web Awesome — сначала в `components.js`.
- Всё состояние — в `store.js`; компоненты наследуют `WorkElement` (`base.js`) и перерисовываются по его изменениям.
- Чистые модули (`router`, `menu`, `api`, `store`) не трогают DOM — они проверяются в Node (`tests/app-shell.test.js`), оболочка — в браузере (`tests/ui/app-shell.html`).
