# Локальная сеть сервера WORK

Агент администратора может осматривать ОС **хоста, на котором запущен WORK**, и находить
устройства в его локальной сети. Это не файловая система и сеть браузера пользователя.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `net_info` | Интерфейсы, CIDR, DNS, маршруты, таблица соседей |
| `net_discover` | Multicast-запросы mDNS/DNS-SD, SSDP, WS-Discovery; для SSDP — описание устройства |
| `net_scan` | TCP connect по профилю портов в разрешённой подсети |
| `net_probe` | HTTP, IPP Get-Printer-Attributes, eSCL capabilities; проверка конкретного OData URL |
| `net_http` | GET в разрешённой сети без автоматических редиректов |
| `net_candidates` | Последние находки с `id`, видом, адресом и основанием определения |
| `net_register` | Создание класса сервиса в `/SERVICES/LAN/<имя>` |

Поиск объявлений — активные multicast-запросы, а не пассивное прослушивание. Каждый интерфейс
опрашивается отдельно. Текущая реализация обнаружения — IPv4. NetBIOS/SNMP не реализованы.
Порт сам по себе не доказывает тип: результат отмечается `port-only`; реклама устройства —
`advertised`; подтверждённый ответ — `ipp`, `escl`, `odata`. Для 1С номер порта — лишь подсказка:
HTTP-публикация требует URL с именем базы, например `http://host/base/odata/standard.odata/`.

## Типичный сценарий

1. `net_info` — выбрать доступную подсеть сервера.
2. `net_discover` — найти объявления принтеров, сканеров и веб-сервисов.
3. `net_scan({cidr: "192.168.1.0/24", profile: "printers"})` — при необходимости проверить порты.
4. `net_probe({host: "192.168.1.20", url: "http://192.168.1.20:631/ipp/print"})`.
5. `net_candidates`, затем `net_register({id, name, kind, endpoint})`.
6. Назначить пользователей на роли класса сервиса. В следующей задаче агент получит `svc_*`.

`NODES` остаётся реестром серверов WORK, `/SERVICES/LAN` содержит коннекторы устройств.
В сетевом кэше (`#system/lan/candidates.json`) ещё нет прав на использование устройств.
Кандидаты дедуплицируются по адресу, порту, виду и endpoint: МФУ может иметь несколько сервисов.

## Коннекторы

* **printer:** `status`, `print({path, format?})` через IPP. Перед печатью проверяется право чтения
  файла WORK и объявленная принтером поддержка MIME. DOCX в PDF автоматически не преобразуется.
* **scanner:** `status`, `scan({to, role, filename?, dpi?, source?})` через eSCL. Одна страница A4,
  PDF или JPEG. Сначала проверяется право записи в зону назначения, затем создаётся задание;
  результат сохраняется штатным `save_file` (история/лента), задание сканера очищается.
* **onec:** `catalogs` (`$metadata`), `query({entity, filter?, select?, top?, skip?})` по OData.
  Только чтение, максимум 500 объектов за вызов. Имя публикации задаёт администратор.
* **web:** `status` читает зарегистрированную страницу.
* **share/sql:** карточка адреса; универсальный SMB/SQL-драйвер не подключается автоматически.
  SMB-путь можно осматривать через `os_*` от имени процесса сервера.

Учётные данные: `credentialFile: "device.json"` в class.js сервиса, а в его `#secret/device.json`
— `{username, password}` или `{token}`. Они не входят в ответ инструмента. HTTPS-сертификаты
проверяются штатно; для внутренних CA нужно настроить доверие процесса Node.

Методы сгенерированных `$service` вызывают `WORK_LAN()` → `connectors.execute`.
Каждый вызов проверяет текущую сессию и доступ к классу сервиса. Подписанному субъекту-узлу
эти локальные коннекторы не выдаются. Обнаружение доступно только корневому ADMIN;
пользователь с назначением на класс может пользоваться конкретным сервисом.

## Конфигурация

`#system/os.json` (необязателен, локальная конфигурация):

```json
{
  "enabled": true,
  "roots": [],
  "deny": [],
  "subnets": ["192.168.1.0/24"],
  "shell": "ask",
  "maxScanHosts": 1024
}
```

Без `subnets` разрешены частные IPv4-сети интерфейсов сервера. `roots: []` разрешает файловым
инструментам ОС любые пути за пределами WORK, кроме встроенных и дополнительных исключений.
UNC работает с учётной записью процесса WORK; введение SMB-паролей в инструмент не требуется.

`net_scan` требует подтверждения каждого запуска, `net_register` — подтверждения регистрации;
печать и сканирование также подтверждаются при вызове агентом. TCP: до 32 соединений одновременно,
до 64 портов, 60 секунд на запуск, частичный результат возвращается с `partial: true`.
Все сетевые HTTP-запросы закрепляют проверенный IPv4 адрес и ограничивают размер/время ответа.
`web_fetch` использует отдельный публичный транспорт, а не доступ к LAN.

## Проверки

`node --test tests/lan.test.js tests/system-os.test.js` — изолированные каталоги и loopback-серверы:
права, ограничение путей/junction, лимиты HTTP, TCP, разбор discovery, IPP, eSCL, OData,
регистрация настоящего класса WORK. Физические устройства этими тестами не используются.
