# sources/modules/agent — ядро агента WORK

## 1. Что это

Исполнительное ядро ИИ-агента: цикл на нативном tool calling, инструменты работы с деревом WORK и внешним миром, политика разрешений, сессия задачи `.task`. Обычные Node-модули (импортируют `node:*`, тестируются напрямую). Слои дерева (`class.js` — data:-модули) получают ядро через глобальные `WORK_AGENT()` (сессия) и `WORK_AGENT_CORE()` (окружение, разовый запуск) — `sources/server/server.js`.

## 2. Зачем это нужно

Один способ работы агента для всех сценариев: модель сама выбирает инструменты и их аргументы (JSON-схемы), независимые чтения идут параллельно, действия с побочным эффектом проходят политику разрешений, человек отвечает и подтверждает прямо в ленте. Лента — единственный источник правды: по ней строится контекст модели, рисует UI, с неё продолжается работа после стопа и рестарта.

## 3. Как это работает

1. **Окружение** (`index.js` `createEnv`): для места (класса) и пользователя собирает system-промпт (`ai/system.md`, среда WORK, место, роли, время, режим, контракт места — собранный readme, навыки, субагенты) и набор инструментов.
2. **Цикл** (`loop.js` `runLoop`): лента → messages (OpenAI-формат; старые результаты урезаются, сжатые элементы заменены сводкой) → `llm.stream` → текст/рассуждение стримятся в UI (`host.emit`) → вызовы инструментов → результаты в ленту → следующий ход, пока модель не ответит без вызовов. Подряд идущие `readonly`/`concurrent` вызовы — параллельно. Лимит ходов, ретраи до первого токена (кроме ошибок ключа), стоп (AbortSignal рвёт HTTP), сжатие контекста при ~72% окна модели.
3. **Разрешения** (`permissions.js`): режимы `auto` | `ask` | `plan`. `readonly` — всегда; `plan` — инструменты записи модели не показываются; `ask` — любое действие с эффектом спрашивает; `auto` — запись в рабочие данные без вопроса, код/конфиг системы (`/$server`, `/sources`, `/oda`, `/MODELS`, `/SERVICES`, `/NODES`, `*.js`, `#security`/`#secret`/`#system`) и `risk:'danger'` — с подтверждением. «Разрешить всегда» — на задачу (`body.allowed`). Права пользователя проверяет само ядро WORK: каждый вызов идёт с `session` (и перебором ролей пользователя в классе).
4. **Сессия** (`session.js`): тело `.task` v2 в памяти, атомарная запись, одна петля на файл (замок), ожидание человека (`host.wait`) — вопрос или подтверждение; ответ, пришедший после рестарта, применяется к ленте и работа продолжается. События: `chat.start`/`chat.done`, `task.state`, `task.delta`, `{path}`.
5. **Разовый запуск** (`runOnce`): REST `/КЛАСС?prompt&prompt=…` без ленты на диске; подтверждаемые действия отклоняются с объяснением.

## 4. Из чего это состоит

| Файл | Роль |
|---|---|
| `index.js` | окружение (`createEnv`), адаптер модели (`llmFor`), разовый запуск (`runOnce`) |
| `loop.js` | цикл, лента → messages, сжатие (`maybeCompact`) |
| `permissions.js` | режимы и защищённые зоны |
| `session.js` | хост `.task` v2: `prompt`, `approve`, `stop`, `revert`, `configure`, `compact`, `getBody` |
| `resources.js` | данные из дерева: `ai/system.md`, `ai/config.js`, `ai/agents/*.md`, `ai/skills/*.md` по слоям (пакет движка → классы от корня к месту) |
| `tools/work.js` | `ls`, `read`, `find`, `write`, `edit`, `create_class`, `schema`, `call`, `logs`, `history`, `restore`, `delete` |
| `tools/services.js` | `web_search`, `web_fetch`, `svc_*` (SCHEMA сервисов `/SERVICES`), `mcp_*` (инструменты MCP-серверов) |
| `tools/meta.js` | `todo_write`, `ask_user`, `task` (субагенты), `skill`, `save_skill`, `generate_image` |
| `mcp-pool.js` | пул stdio MCP-серверов: процесс живёт между вызовами, простой 5 мин — закрыть, падение — перезапуск при следующем вызове |
| `diff.js` | построчный diff для карточек правок |
| `util.js` | id, обрезка, оценка токенов, фронтматтер |

Элементы ленты: `user` · `assistant` (`content`, `reasoning`, `tools[]` со статусами `pending|approval|waiting|running|ok|error|denied|interrupted|approved`) · `summary` · `error`. Субагент хранит свою ленту в `tools[].items`.

Инструмент: `{ name, description, parameters, readonly?, concurrent?, planSafe?, risk?:'write'|'danger', target?(args), permission?(args), run(args, ctx) }`; `ctx`: `session`, `place`, `env`, `host`, `llm`, `entry` (карточка вызова — сюда `path`, `diff`, `items`), `signal`, `depth`.

## 5. В каком это состоянии

Работает: очередь реплик во время работы (`body.queue` → в ленту между ходами), картинки из вложений модели с `vision`, пул MCP-процессов, цикл, параллельные чтения, разрешения, вопросы/подтверждения (в т.ч. после рестарта), субагенты, навыки (загрузка и сохранение), сервисы и MCP как инструменты, сжатие контекста, стоп/продолжение/откат. Проверено тестами `tests/agent-core.test.js` (сценарная модель) и живыми прогонами на `/MODELS/odant/Qwen3.8 27b` (`scripts/agent-run.mjs`).
