# sources/modules/rag/ — RAG WORK

Смысловой поиск по дереву WORK, который **видит ровно то, что доступно пользователю**,
и ищет **от точки взаимодействия, расходясь кругами**. Права — общие с ядром
(`sources/server/access`), своих правил доступа у модуля нет.

## Файлы

| Файл | Роль |
|---|---|
| `index.js` | фасад `RAG`: `start/stop`, `invalidate`, `search`, `queryObjects`, `clear`, `reconcile`, `status` |
| `config.js` | модель, нарезка, лимиты, исключения, веса поиска; версия индекса = модель \| чанкер |
| `store.js` | SQLite (`.index/work.db`, node:sqlite): документы, содержимое по hash, чанки + векторы + FTS5, назначения, реестр классов |
| `extract.js` | документы по физическому пути: `file`, `object` (карточка `$data` по схеме), `log` (запись ленты), `class` (карточка класса) |
| `chunker.js` | нарезка с учётом заголовков markdown, абзацев, предложений; перекрытие внутри раздела |
| `embedder.js`, `embed-worker.js` | эмбеддинги в worker_threads (transformers.js), пакетами |
| `indexer.js` | очередь по событиям, сверка с диском, fs.watch корня |
| `scope.js` | проекции точки (слои `~`), области документов, контексты пользователя (кольца) |
| `search.js` | гибридное ранжирование, проверка прав на выходе; `queryObjects` |

## Индексация

- **Физически, один раз**: документ = физический файл; содержимое адресуется по `sha256(версия | вид | текст)`.
  Живой файл и его снимки, копии одной записи в нескольких лентах — одни чанки и эмбеддинги.
- **По событиям**: `save_file` / `$file.save` / `delete` ядра → `globalThis.WORK_RAG.invalidate(path)`;
  внешние правки — `fs.watch` корня (дебаунс 1 с); при старте — сверка диска и индекса (через 15 с).
- **Виды**: `file` — md/txt/office/pdf (код — только при `WORK_RAG_CODE=1`); `object` — файлы данных
  (`.oml`, `.eml`, `.ics`, `.task`…): карточка «Поле: значение» по `METADATA.FIELDS` класса-владельца
  со всеми слоями, поле `rag: false` не индексируется; `log` — одна запись ленты; `class` — карточка класса
  (label, тип, описание, поля) + назначения ролей из `#security`.
- **Не индексируются**: `node_modules`, `sources`, `oda`, `tests`, `scripts`, `#secret`, `#system`, скрытые `.…`
  (кроме снимков, на которые ссылается чья-то лента — индексируются по требованию).
- Смена модели или формата карточек (`CONFIG.chunker`) сбрасывает индекс — сверка пересобирает его.

## Поиск

Контекст — пара (точка, роль) с весом близости:

1. точка с **активной ролью** (`params.role`), затем
2. **своя лента** (кабинет): свои записи и то, на что они указывают,
3. точка с **другими ролями** пользователя,
4. точки на расстоянии 1…`rings` по дереву организации, где у пользователя есть роли
   (для `scope=subtree` — и все нижестоящие).

Для контекста документы берутся из **проекции точки**: физические папки слоёв `~` (`_tilde_layers` +
цепочки `inherit_ancestor`), путь документа в точке = метапапка точки + типизирующий хвост слоя +
относительный путь. При совпадении относительного пути побеждает ближний слой (своя точка → вышестоящие
классы → корневые типы). Область документа и право чтения — `access/policy.js`, как в `canSee`.

Ранжирование: косинус по векторам + BM25 (FTS5), слияние RRF, × вес контекста × вес слоя; не больше
2 фрагментов на документ. Итоговые фрагменты проверяются настоящим `canSee` точки.

Результат: `{path, source?, point, role?, via, kind, title, heading?, text, start, end, score}`.
`path` — виртуальный путь **в точке**: по нему файл открывается с правами этой точки
(для унаследованного файла `source` — физический путь).

## Запуск и отладка

- Сервер: `RAG.start()` в `sources/work.js`; `WORK_RAG=0` — выключить фоновую индексацию.
- `rag_status()` на любом элементе — очередь, счётчики, последние ошибки; `clear_rag()` (ADMIN) — переиндексировать поддерево.
- Агент: инструмент `search` (`sources/modules/agent/tools/work.js`).
