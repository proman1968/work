# MCP-сервер WORK

WORK как MCP-сервер: внешние ИИ-клиенты (OpenCode, Claude Code, Copilot в VS Code) работают с деревом организации теми же инструментами, что и встроенный агент, и с правами выпустившего токен пользователя.

## Что это

Конечная точка `POST /mcp` (Streamable HTTP, JSON-RPC 2.0): `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`; `DELETE /mcp` закрывает сессию (`Mcp-Session-Id`). Инструменты — **те же реализации**, что у агента: `ls`, `read`, `find`, `search`, `query`, `logs`, `history`, `send`, `write`, `edit`, `call`. Удаление и откат наружу не отдаются.

## Зачем

Разрабатывать и администрировать WORK, не заходя в его интерфейс: открыть репозиторий в OpenCode/Claude Code и подключить организацию как MCP-сервер — агент читает контракты мест, ищет, пишет файлы, вызывает методы классов, а WORK проверяет права и спрашивает человека, где нужно.

## Как подключить

Пользовательская инструкция (токен, конфиги клиентов, подтверждения, частые проблемы) — **`docs/work-mcp.md`**.

1. Войдите в WORK, откройте профиль → **«Токен для MCP»** → подтвердите. Токен `wmcp.<uid>.<секрет>` показывается **один раз** (скопируйте). «Отозвать токены MCP» отключает все клиенты.
2. Адрес сервера — `http://<хост>:<порт>/mcp` (по умолчанию `http://localhost:8001/mcp`).
3. Настройка клиента (формат конфигов у клиентов меняется — сверяйтесь с их документацией):

```jsonc
// OpenCode: opencode.json
{ "mcp": { "work": { "type": "remote", "url": "http://localhost:8001/mcp", "headers": { "Authorization": "Bearer wmcp.…" }, "enabled": true } } }
```

```bash
# Claude Code
claude mcp add --transport http work http://localhost:8001/mcp --header "Authorization: Bearer wmcp.…"
```

```jsonc
// VS Code (Copilot): .vscode/mcp.json
{ "servers": { "work": { "type": "http", "url": "http://localhost:8001/mcp", "headers": { "Authorization": "Bearer wmcp.…" } } } }
```

Пути в инструментах — абсолютные (`/КЛАСС/…`). Токен лучше хранить в переменной окружения клиента, а не в репозитории (сканер секретов `npm run check:secrets` ловит токены формата `wmcp.…` только если они попали в файлы).

## Безопасность

| Что | Как |
|---|---|
| Откуда | Только с localhost и частных сетей: проверяется адрес соединения и **каждый** адрес из `X-Forwarded-For` (обратный прокси не открывает доступ извне). Иначе 403. `WORK_MCP=0` выключает точку (404) |
| Браузер | Запросы с чужим `Origin` — 403; CORS не разрешён |
| Токен | `Authorization: Bearer`; хранится только **хеш** секрета, файл `USERS/<uid>/$user/#secret/mcp-tokens.json` зашифрован (AES-256-GCM, AAD = uid); до 10 токенов на пользователя; 10 неверных попыток с адреса за 10 минут → 429. Токены выпускает только вошедший человек (сессия MCP токены выпускать не может) |
| Права | Пользователь токена и (необязательная) роль токена; проверяет ядро WORK (`callAs` → `assertAccess`) так же, как для агента. Обычный пользователь пишет в свою зону класса |
| Политика | Каждый вызов проходит `decide()` (`agent/permissions.js`): код и системные пути, опасные методы — только с подтверждением |
| Правила организации | Хуки `pre_tool`/`post_tool` ближайшего класса (`agent/hooks.js`) действуют и через MCP |
| Чужое содержимое | Письма и т.п. приходят в `<untrusted>`; после них внешние действия (`send` людям, опасные `call`) — только с подтверждением. Заражение живёт на токен (повторный initialize не отмывает); подтверждение человека через elicitation относится к ОДНОМУ вызову (R14/8.38) — заражение сессии не снимается, следующее действие наружу снова спросит; снимает только конец сессии/отзыв токена |
| Подтверждение | `elicitation/create` по SSE (клиент должен объявить `capabilities.elicitation` и принимать `text/event-stream`); без этого — отказ с понятным текстом. «Разрешить всегда» нет. Таймаут вопроса — 5 минут |
| Аудит | Каждый вызов — запись `mcp` в журнале безопасности (инструмент, цель, вердикт, итог, клиент, id токена); отказы входа — `mcp_reject`; выпуск/отзыв токенов — `mcp_token` |

## Из чего состоит

| Файл | Назначение |
|---|---|
| `server.js` | `/mcp`: проверки адреса/Origin/токена, JSON-RPC, сессии, `tools/list`, `tools/call` (хуки → политика → подтверждение → инструмент → аудит), elicitation по SSE |
| `tokens.js` | выпуск, проверка, отзыв токенов (хеш, шифрование, лимиты) |

Методы выпуска — `mcp_token_create/list/revoke` в `host/auth-methods.js` (уровень `USER` в шлюзе доступа); кнопки — `modules/user-profile`.

## Состояние

Работает: инициализация и сессии, список и вызов инструментов, права и роль токена, политика, хуки организации, заражение, elicitation, аудит, выпуск и отзыв токенов (профиль). Проверено тестами `tests/mcp.test.js` (настоящий HTTP-сервер, SSE-клиент) и мутационно; **живой прогон с OpenCode/Claude Code не выполнялся**.
