# Счета в журнале проводок ($register)

1. Определи целевой журнал `$register`: если задача запущена внутри журнала или его счёта — используй путь этого журнала (например `/ORGANIZATIONS/<Организация>/MODULES/Register/REGISTER` или `/MODULES/Register/REGISTER`). Прочитай контракт `read` журнала и проверь `ls` журнала — какие счета уже созданы (их не трогать и повторно не создавать).
2. Состав счетов — из запроса пользователя; если не указан — типовой набор:
   41 Товары, 43 Готовая продукция, 50 Касса, 51 Расчётные счета, 60 Расчёты с поставщиками,
   62 Расчёты с покупателями, 66 Краткосрочные кредиты, 67 Долгосрочные кредиты,
   68 Расчёты по налогам и сборам, 69 Расчёты по социальному страхованию, 70 Расчёты с персоналом,
   71 Расчёты с подотчётными лицами, 76 Расчёты с разными дебиторами и кредиторами, 90 Продажи,
   91 Прочие доходы и расходы, 99 Прибыли и убытки.
   Набор шире 5 счетов — покажи список и спроси подтверждение (`ask_user`) до создания.
3. Каждый счёт — `create_class`: `parent` = путь журнала `$register` (для субсчёта — путь родительского счёта `$account`), `id` = код счёта, `type` = `$account`, `label` = «NN Название», `class_js` = `export default { icon: '<набор:имя>' }`.
   Иконка обязательна, только из наборов `carbon:`, `icons:`, `ai:`, `lineawesome:`, `bootstrap:`, `iconoir:`, `editor:` (например `carbon:receipt`, касса — `carbon:wallet`); набора `register:` нет.
   Независимые создания можно выполнять параллельно в одном ходе.
4. Проверка: `ls` журнала — все счета на месте; выборочно `describe_class` или `read` одного счёта (код, `label`, `icon`).
5. Итог: таблица «код — название — путь», какие счета уже существовали и были пропущены.
