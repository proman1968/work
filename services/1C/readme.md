# 1C

## Что это

Коннектор `$service` к информационной базе 1С через штатный OData-интерфейс. Даёт ИИ и коду work читать справочники, документы и прочие EntitySet без записи в базу.

## Зачем это нужно

Чтобы агенты и сценарии work обращались к данным учёта 1С тем же способом, что к SearXNG или DuckDuckGo: `WORK.get_item('/SERVICES/1C')` и методы сервиса. Один общий OData-слой — без привязки к конкретной конфигурации (УТ, БУХ и т.п.).

## Как это работает

В форме сервиса задаются `baseUrl` (корень публикации ИБ), `login` и `password` (Basic-auth). К `baseUrl` дописывается `/odata/standard.odata`.

Типичный порядок для ИИ:

1. `list_entities` — имена EntitySet из `$metadata` (`Catalog_*`, `Document_*`, …)
2. `query` — выборка с `$filter` / `$select` / `$top` / `$skip` / `$orderby`
3. `get` — одна запись по `Ref_Key` (GUID)

Ответ: `{ source: '1C', … }` или `{ error }`. Запись в 1С не поддерживается.

## Из чего это состоит

- `$service/class.js` — класс сервиса: METADATA, SCHEMA, `list_entities` / `query` / `get` (коннектор OData только на чтение)

## В каком это состоянии

- ✅ чтение через OData: `list_entities`, `query`, `get`
- ❌ запись / проведение документов
- ❌ встройка в `pipe.js` задач

## Дальнейшие планы

- Методы записи при отдельном согласовании прав
- Подключение к сценариям задач (`pipe`), когда понадобится прикладной кейс
