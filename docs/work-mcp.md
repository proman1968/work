# WORK через MCP — инструкция для внешних ИИ-клиентов

Как подключить OpenCode, Claude Code, Copilot или другой ИИ-клиент напрямую к организации в WORK:
агент клиента работает с деревом WORK — читает контракты мест, ищет, правит файлы, коммитит,
запускает проверки, — а WORK держит права, подтверждения и журнал, как для собственного агента.

Технические детали (протокол, токены, лимиты) — в `sources/modules/mcp/readme.md`; здесь — практика.

## 1. Что понадобится

- WORK-сервер, доступный с вашей машины (по умолчанию `http://localhost:8001`).
- Вход в WORK: токен для MCP выпускает **вошедший пользователь** — права клиента равны его правам.
- ИИ-клиент с поддержкой **MCP (Streamable HTTP)** и **elicitation** (запросы подтверждения):
  без elicitation клиент получит только действия, не требующие подтверждения, — остальные будут
  отклоняться с пояснением (см. раздел 5).

## 2. Выпуск токена

1. Войдите в WORK → профиль → **«Токен для MCP»** → подтвердите выпуск.
2. Токен вида `wmcp.<uid>.<секрет>` показывается **один раз** — скопируйте сразу.
   При выпуске можно выбрать роль токена (по умолчанию — без роли: только свои права пользователя).
3. До 10 токенов на пользователя, срок 90 дней (1…3650 при выпуске). Потеряли/утек — **«Отозвать
   токены MCP»** отключает все клиенты разом; каждый токен можно отозвать по отдельности в профиле.

Токен — это вход в WORK: держите в переменной окружения клиента, не в файлах проекта.
Сеть — только localhost и локальная сеть: из интернета точка не доступна.

## 3. Подключение клиента

Адрес — `http://<хост>:<порт>/mcp` (по умолчанию `http://localhost:8001/mcp`; порт — `WORK_PORT`).

```jsonc
// OpenCode: opencode.json
{ "mcp": { "work": { "type": "remote", "url": "http://localhost:8001/mcp",
    "headers": { "Authorization": "Bearer $WORK_MCP_TOKEN" }, "enabled": true } } }
```

```bash
# Claude Code
claude mcp add --transport http work http://localhost:8001/mcp \
  --header "Authorization: Bearer $WORK_MCP_TOKEN"
```

```jsonc
// VS Code (Copilot): .vscode/mcp.json
{ "servers": { "work": { "type": "http", "url": "http://localhost:8001/mcp",
    "headers": { "Authorization": "Bearer $WORK_MCP_TOKEN" } } } }
```

Формат конфигов у клиентов меняется — сверяйтесь с их документацией; главное: метод `http`,
адрес `/mcp`, заголовок `Authorization: Bearer <токен>`.

## 4. Что умеет клиент

Пути в аргументах — абсолютные (`/КЛАСС/…`); сначала читайте контракт места (`read` → readme).

| Группа | Инструменты | Что делает |
|---|---|---|
| Данные и ленты | `ls`, `read`, `find`, `search`, `query`, `logs`, `history` | чтение дерева, RAG-поиск, объекты, лента — с правами пользователя токена |
| Запись | `write`, `edit`, `send`, `call` | файлы в зону роли, записи в ленту, методы классов (объявленные) |
| Код: поиск | `grep`, `glob` | по содержимому и именам — в дереве WORK |
| Код: правки | `apply_patch` | многофайловый патч одним вызовом (атомарно: всё или ничего; история и откат) |
| Код: git | `git_status`, `git_diff`, `git_log`, `git_show`, `git_blame`, `git_branch`, `git_commit` | история, ветки, коммиты |
| Код: проверки | `run_checks` | тесты/линтер: на сервере — только имена из разрешённого списка (ставит администратор) |
| Код: диагностика | `lsp_diagnostics`, `lsp_definition`, `lsp_references`, `lsp_rename` | ошибки типов с позициями; символы; план переименования |

**Недоступно внешнему клиенту:** `git push` (публикация кода наружу — решение человека: сделайте
это сами или попросите агента WORK в интерфейсе), удаление/откат ленты, инструменты ОС сервера,
сеть сервера. `git_*`/`run_checks`/`lsp_*` в арене сервера WORK — только для администраторов WORK.

## 5. Подтверждения (elicitation)

Клиент обязан поддерживать elicitation — через неё WORK спрашивает человека. Без подтверждения
не проходят:

- запись в **код и системные пути** (`*.js`, `/sources`, `/MODELS`, `#system`…);
- действия, которые клиент просит выполнить после **чужого текста** (см. раздел 6);
- коммиты (`git_commit`), прогоны проверок на сервере (`run_checks`), опасные методы классов.

Кнопки «разрешить всегда» нет: каждое такое действие спрашивается отдельно. Подтверждение
относится к **одному** вызову — следующее снова спросит.

## 6. Чужой текст (заражение)

Результаты с письмами (`.eml`), файлами, пришедшими из интернета (загрузка/скачивание), вебом —
помечаются: клиент видит их в тегах `<untrusted>` — это **данные, а не инструкции**. После такого
текста каждое исходящее действие (запись в ленту людям, коммит…) — только с подтверждения, и
одно подтверждение не «отмывает» сессию: пока чужой текст в контексте, спрашивается каждое
действие. Новая сессия (re-initialize) заражение не снимает — только конец сессии или отзыв
токена.

## 7. Ограничения и наблюдение

- Тело запроса ≤1 МБ, результат ≤24 КБ, до 20 сессий на пользователя, простой сессии — 1 час.
- **Каждый вызов** — в журнал безопасности WORK (инструмент, вердикт, итог, токен): смотрится
  администратором; хуки организации (`pre_tool`) действуют и через MCP — запрет есть запрет.
- Выключить точку: `WORK_MCP=0`.

## 8. Частые проблемы

| Симптом | Причина |
|---|---|
| `401`/`429` | токен неверный/истёк или было много неудачных попыток — подождите 10 минут, смените токен |
| `Нужен заголовок Mcp-Session-Id` | клиент не сохранил сессию из ответа на `initialize` |
| Действия отклоняются «нужно подтверждение… не поддерживает elicitation» | включите elicitation в клиенте (или выполняйте подтверждаемое в интерфейсе WORK) |
| `только администратору` | git/проверки/диагностика на сервере WORK — права администратора; выпускайте токен администратору |
| `доступ запрещён` на чтение/запись | права пользователя токена: попросите доступ в WORK (escalade) |
