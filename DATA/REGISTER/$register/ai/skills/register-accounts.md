# Счета в журнале /DATA/REGISTER

1. `read /DATA/REGISTER` — контракт журнала и типа `$account`; `ls /DATA/REGISTER` — какие счета уже есть (их не трогать, повторно не создавать).
2. Состав счетов — из реплики пользователя; если не указан — типовой набор:
   41 Товары, 43 Готовая продукция, 50 Касса, 51 Расчётные счета, 60 Расчёты с поставщиками,
   62 Расчёты с покупателями, 66 Краткосрочные кредиты, 67 Долгосрочные кредиты,
   68 Расчёты по налогам и сборам, 69 Расчёты по социальному страхованию, 70 Расчёты с персоналом,
   71 Расчёты с подотчётными лицами, 76 Расчёты с разными дебиторами и кредиторами, 90 Продажи,
   91 Прочие доходы и расходы, 99 Прибыли и убытки.
   Набор шире 5 счетов — покажи список и спроси подтверждение (ask_user) до создания.
3. Каждый счёт — `create_class`: `parent` = `/DATA/REGISTER` (субсчёт — родительский счёт), `id` = номер счёта, `type` = `$account`, `label` = «NN.00 Название», `class_js` = `export default { icon: '<набор:имя>' }`.
   Иконка обязательна, только из наборов `carbon:`, `icons:`, `ai:`, `lineawesome:`, `bootstrap:`, `iconoir:`, `editor:` (например `carbon:receipt`, касса — `carbon:wallet`); набора `register:` нет.
   Независимые создания можно делать подряд в одном ходе.
4. Проверка: `ls /DATA/REGISTER` — все счета на месте; выборочно `read` одного счёта (номер, `label`, `icon`).
5. Итог: таблица «номер — название — путь», какие счета уже были и пропущены.
